### 1.3 問題点

**A. 同じ情報が何か所にもある**
1. `Wall` が、質点ごとの配列（`dx_is`、`gma_is`、`material_is`、`is_air_layer_is`）と、質点の部品 `cells_is`（幅と材料を持つ）の両方を持つ。
2. 状態の持ち方が 3 通りある：`WallState`（使われていない）、`State` のリスト `state_n_is`、配列 `t_n_is`・`wp_n_is`。どれが正しい値かがわからない。
3. 雨水の設定が、`RainLeakage` のリスト（`rain_leakage_is`）と、`Cell` の項目（`ratio`、`v_threshold`）の両方にある。
4. 表面の熱伝達率が、`Layer`（最初の層の `cond_h_o` = 22.4 など）と定数（`COND_H_O` = 22.4）の両方にあり、`Cell` は定数のほうを使う。`Layer` の値は使われていない。

**B. 境目（層と層、層と空気）の扱いが部品に混ざっている**
1. `Cell` のサブクラス 8 種類の違いは、「質点が検査体積のどこにあるか」（中心か、表面・境目の上か）と、「両隣に何があるか」（外気・室内・通気層・ほかの層）の組み合わせ。この 2 つは別々の情報なのに、組み合わせごとにクラスを作っている。
2. 層と層の接触の抵抗（`Layer.cond_h_o`・`cond_h_i` など）を、**両側の層がそれぞれ持っている**。例：構造用合板の `cond_h_i` = 50 と、隣のグラスウールの `cond_h_o` = 50 が直列に入り、境目のコンダクタンスが 50 ではなく 25 になる。防湿層（GW–合板の 2.0×10⁻¹¹）も実質 1.0×10⁻¹¹ になっている。1 つの境目の値は 1 か所で持つべき。
   - **Fortran の扱い**（2026-10-21 確認、`_fortran/Whamcavity.f95` 880〜945 行）：層の左端の質点は自分の層の「外面」の値 `ALF(K,1)` だけ、右端の質点は自分の層の「内面」の値 `ALF(K,2)` だけを使う（直列にも平均にもしない。湿気の `ALD` も同じ）。入力（`_fortran/mw1-d.dat`）では、どの境目も両側に同じ値が入っているので、**境目ごとに 1 つの値として働く**。両側に違う値を入れると、境目で熱・水分が保存されなくなる。
   - 今の Python の直列の扱いは、移植のときに変わったもの。
2b. **表面の値が入力ではなく定数で決まっている**（2026-10-21 確認）：`CellOutsideSurface`・`CellInsideSurface` は、層の入力値ではなく `thermo_dynamics` の定数（`COND_H_O`、`COND_M_I` など）を使う。熱（22.4・9.2）と外側の湿気（2.0×10⁻¹¹）はたまたま入力と同じ値だが、**室内側の湿気は入力が 2.6×10⁻¹⁰**（斎藤先生のコメントの「塗膜やクロスなどの透湿抵抗」に当たる）**なのに、定数 3.43×10⁻⁸ が使われ、約 130 倍湿気を通しやすい**。外側の湿気 2.0×10⁻¹¹ も、ふつうの表面の湿気伝達率（3.4×10⁻⁸ 程度）ではなく、サイディングの塗装の透湿抵抗を含めた値と見られる。
3. 方程式を作る `Wall.get_t_next_is`・`get_wp_n_pls` が、`isinstance(cell, CellOutsideSurface)` などで境界を見分けている。

**C. 物理と解き方が混ざっている**
1. `Wall` が、壁の構成（変わらないもの）、状態（時間で変わるもの）、方程式の係数、反復の 1 回分の計算、水膜・雨水・通気・木材腐朽の水分を、全部持っている（約 800 行）。
2. 反復法（1 点ずつ、緩和係数つき）と、物理の係数の計算が同じ関数の中にある。収束の判定は `main.py` にある。
3. 水分の式の中に、物理の定数（`PXCOF`、湿気伝達率 3.43×10⁻⁸、濡れ面積率 0.3）が直書きされている。

**D. 入力の読み込みが不完全**
1. `Wall.read` は入力を使わず、層の構成を直書きしている。`Layer` に必要な初期温度・湿度を渡していないので、`TypeError` で止まる。`Wall` の `height`・`wp_n_is` も渡していない。
2. `InputRoom.read` が値を返さない。`InputWall.read` は numpy を import していない。
3. `WallSurface` が、持っていない項目（`absorption`、`emissivity`、`eva_height`）を使う（項目名は `eva_heigt`）。
4. 通気層かどうかを、層の名前が「通気層」かで判定している。

**E. 時間の進め方が Fortran の形のまま**
1. `main.py` の年・月・日・時・分割の 5 重ループ。`Period.get_start_day` が存在しない項目 `NDAY1` を使う。
2. 未定義の変数（`rn_ws_is`、`month`、`day` など）があり、木材腐朽の計算がループの中に直書きされている。
3. 計算の設定（`NDVD`、`OMG`、`EPS1` など）が `config.py` の定数で、入力から変えられない。

**F. 小さなバグ**（直すときに一緒に直す）
- `Wall.get_wp_n_pls` で `cap_m(state=self.state_n_is)` と、リストをそのまま渡している。
- 雨水の設定 `get_nrains_of_walls(wall_index=i)` の `i` が、前の行のループの変数の残り（たまたま 0）。

## 2. 目指す構造の案

### 2.1 考え方

1. **変わらないもの**（壁の構成・材料・質点の並び）と、**時間で変わるもの**（温度・水分）を分ける。
2. **1 つの情報は 1 か所に**持つ。
3. **境目は「つながり」として表す**。質点（容量）と、隣り合う 2 つの質点のつながり（抵抗）を別の部品にする。境界の違いは、つながりの種類（材料の中・層と層の接触・表面の伝達）で表し、`isinstance` で見分けない。
4. **物理（係数・方程式）と、解き方（反復・連立方程式）を分ける**。
5. **入力の読み込みと確認は入口で 1 回**。中の部品は、確認済みの値だけを受け取る。
6. **付け足しのモデル**（通気層の換気、雨水、水膜、木材腐朽）は、差し込める部品にする。

### 2.2 部品の案

```
入力（dict / JSON）
  └─ SimulationInput（確認済みの入力）
       ├─ 計算の設定（期間、時間刻み、収束の条件）
       ├─ 場所（緯度・経度）、気象データのファイル
       ├─ RoomInput（室内の条件）
       └─ WallInput × 壁の数
            ├─ SurfaceInput（方位・傾斜・日射吸収率・放射率・高さ）
            ├─ LayerInput × 層の数（材料の出どころ＋名称、厚さ、分割数、通気層かどうか、初期の温湿度）
            └─ InterfaceInput × 境目の数（接触の熱・湿気コンダクタンス。境目ごとに 1 つ）

壁の形（変わらないもの）：WallGeometry
  ├─ Node × 質点の数：検査体積の幅、質点から検査体積の左右の端までの距離、材料（通気層なら空気）、どの層か
  └─ Link × つながりの数（質点の数 ＋ 1）：
       左右の質点（端は外気・室内）、境目の抵抗
       抵抗 ＝ 左の質点の右側の距離 / λ ＋ 境目の抵抗 ＋ 右の質点の左側の距離 / λ（2.3 節）

状態（時間で変わるもの）：WallState
  └─ 温度 [I]、水分化学ポテンシャル [I]（numpy の配列）。相対湿度などはここから計算

境界条件：BoundaryCondition（ある時刻の外気・室内・日射・雨）
  └─ Weather・Room・Surface から作る

解く部分：Solver
  └─ step(壁の形, 状態 n, 境界条件 n+1, 時間刻み) → 状態 n+1
       ├─ 係数を作る（Node の容量、Link の伝導率。状態による）
       └─ 解く（今の反復法、または三重対角の連立方程式）

時間の進め方：Simulation
  └─ 時刻の並びを 1 本のループで進め、壁ごとに Solver を呼び、結果を記録する

付け足しのモデル（Solver に差し込む）
  ├─ 通気層の換気（熱・水分の出入り）
  ├─ 雨水の浸入・水膜
  └─ 木材腐朽（1 日ごとに状態から計算する後処理）
```

### 2.3 質点の置き方とつながりの抵抗

今のコード（`Layer.dx`、`Wall.read`、`cell.py`）の質点の置き方を、そのまま引き継ぐ。厚さ d、分割数 n の層では、質点の間隔は dx = d / (n − 1) で、**層の両端（表面・異種材料の境目）に必ず質点がある**。

```
      層A（材料A）                    層B（材料B）
外気 |●───●───●───●|  接触抵抗  |●───●───●───●| 室内
     a1  a2  a3  a4               b1  b2  b3  b4
     ↑表面          ↑層の端        ↑層の端          ↑表面
```

- **層の中の質点**（a2、a3 など）：検査体積の中心にある。幅 dx、左右の端までの距離はどちらも dx / 2。
- **層の端の質点**（a1、a4、b1、b4）：質点は**表面・境目の上**にあり、検査体積は層の内側にだけある。幅 dx / 2、表面・境目の側までの距離は 0、層の内側の端までの距離は dx / 2。
- **異種材料の境目**：a4 と b1 は、**ほとんど同じ位置にある 2 つの質点**で、その間は接触抵抗だけでつながる。
- **通気層**：よく混ざった空気の 1 つの質点（分割数 1）。幅は空気層の厚さ、左右の端までの距離は 0。
- 幅の合計は (n − 2)·dx + 2·(dx / 2) = d で、層の厚さと合う。

| 質点の位置 | 幅（容量に使う） | 左の端までの距離 | 右の端までの距離 |
|---|---|---|---|
| 層の中 | dx | dx / 2 | dx / 2 |
| 層の左の端（外気側の表面・境目の上） | dx / 2 | 0 | dx / 2 |
| 層の右の端（室内側の表面・境目の上） | dx / 2 | dx / 2 | 0 |
| 通気層 | 空気層の厚さ | 0 | 0 |

**つながりの抵抗** ＝ 左の質点の右側の距離 / λ ＋ 境目の抵抗 ＋ 右の質点の左側の距離 / λ（湿気・液水も同じ形で、λ を湿気伝導率・液水伝導率に替える。端が外気・室内なら、その側の項はない）

| つながり | 左の質点の分 | 境目の抵抗 | 右の質点の分 | 合計 |
|---|---|---|---|---|
| 外気–a1 | なし | 外表面の伝達 1 / α_o | 0 | 1 / α_o |
| a1–a2 | (dx/2) / λA | 0 | (dx/2) / λA | dx / λA |
| a3–a4 | (dx/2) / λA | 0 | (dx/2) / λA | dx / λA |
| a4–b1 | 0 | 接触抵抗（**1 回だけ**） | 0 | 接触抵抗 |
| b4–室内 | 0 | 内表面の伝達 1 / α_i | なし | 1 / α_i |
| 材料–通気層 | 0 | 通気層の中の伝達 | 0 | 通気層の中の伝達 |

コードの形（考え方を示すだけ。名前や細かい点は段階 2 で決める）：

```python
@dataclass
class Node:
    width: float          # 検査体積の幅, m（熱容量・水分容量に使う）
    d_left: float         # 質点から検査体積の左の端までの距離, m
    d_right: float        # 質点から検査体積の右の端までの距離, m
    material: Material

@dataclass
class Link:
    left: Node | None     # None は外気
    right: Node | None    # None は室内
    r_h_interface: float  # 境目の熱抵抗（層の中は 0、異種材料は接触、端は表面の伝達）

    def r_h(self) -> float:
        r_left = self.left.d_right / self.left.material.lambda_h if self.left else 0.0
        r_right = self.right.d_left / self.right.material.lambda_h if self.right else 0.0
        return r_left + self.r_h_interface + r_right
```

今の `Cell` との関係：今の `CellInterior` は左右に 幅 / 2 / λ、端の `Cell`（幅 dx / 2）は内側に 幅 / λ、境目・表面の側に 1 / コンダクタンス を持ち、`Wall` が隣り合う 2 つを足している。案はこれと同じ計算を、**境目の値を 1 か所に持つ形**で表す。接触抵抗の二重の分（1.3 B-2）を除けば、計算結果は変わらない。

**段階 2 のテストで確かめること**
- 1 層の壁で、全部のつながりの抵抗の合計が 1/α_o ＋ d/λ ＋ 1/α_i になる。
- 2 層の壁で、合計が 1/α_o ＋ dA/λA ＋ 接触抵抗 ＋ dB/λB ＋ 1/α_i になる。
- 今の `Cell` で計算した抵抗と、つながりごとに一致する（接触抵抗の二重の分は除く）。
- 幅の合計が層の厚さになる。

## 3. 進める順番の案

下の部品から作り、1 つずつテストで確かめる。**新しい部品を今のコードの横に作り、置き換えが終わったら古いものを消す**（途中で動かなくなる部分を増やさないため）。

| 段階 | 作るもの | 確かめ方 |
|---|---|---|
| 1 | 入力：`LayerInput`・`InterfaceInput`・`SurfaceInput`・`WallInput`（読み込みと確認） | 正しい入力が読める、足りない・おかしい値でわかりやすいエラー |
| 2 | 壁の形：`Node`・`Link`・`WallGeometry`（入力から作る） | 質点の数・幅の合計が層の厚さ、1 層の壁の熱抵抗の合計が 表面 ＋ d/λ ＋ 表面 |
| 3 | 状態：`WallState` | 初期の温湿度から作れる、相対湿度との換算 |
| 4 | 解く部分（熱だけ） | 1 層の壁の定常の熱流が手計算と合う、一様な温度なら変わらない、熱量の保存 |
| 5 | 解く部分（水分も） | 一様な状態なら変わらない、水分量の保存、透湿だけの定常の流れ |
| 6 | 時間の進め方：`Simulation`、境界条件 | 一定の外気・室内で定常に近づく |
| 7 | 付け足しのモデル（通気層・雨水・水膜・木材腐朽） | それぞれの単体のテスト |
| 8 | 古い部品を消す（`cell.py`、`Wall` の古い部分、`main.py` の書き換え） | 全テストが通る |

## 4. 決めてほしいこと

1. **質点とつながりに分ける案（2.2・2.3）でよいか**。今の `Cell` の 8 種類を残して中を整理する方法もある（変更は小さいが、境目の値の二重持ち（1.3 B-2）は残りやすく、表面の塗膜や雨水の浸入点などを足すたびにクラスが増える）。
2. ~~層と層の接触の値を、境目ごとに 1 つにするか~~ → **境目ごとに 1 つの値にする**（2026-10-21 決定）。表面（外気側・室内側）も境目の 1 つとして扱い、熱と湿気の値を入力から取る。層が n 枚なら境目は n + 1 個。Fortran の形の入力（層ごとに外面・内面）を読むときは、境目の両側の値が同じかを確かめ、違えばエラーにする。理由は 1.3 B-2（Fortran も実質そう働いていた）。
3. **連立方程式の解き方**：今の反復法（1 点ずつ、緩和係数 1.2）を残すか、三重対角の連立方程式を直接解く方法にするか。直接解くほうが速く、収束の問題がない。物理は同じ。
4. **入力の形**：dict（Python）だけでよいか、JSON などのファイルからも読むか。
5. **この文書の置き場所**：`docs/design/class_structure.md`（公開リポジトリ）でよいか。
